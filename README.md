Static landing page served via GitHub Pages. **Was** the target of the Web RedirectUri on
the DGT Management multi-tenant Entra apps (Standard + Elevated) **until the 2026-04-23 rebrand**.

When a client's Global Administrator clicks an admin-consent URL like

```
https://login.microsoftonline.com/{client-tenant-id}/adminconsent?client_id={app_id}
```

and grants consent, Microsoft redirects the browser to the configured Web
RedirectUri on the app. Originally `https://localhost`, which left admins
staring at a browser "can't reach this page" error — confusing because the
consent itself succeeded. This repo hosted a single `index.html` that renders a
clean "consent recorded" acknowledgment instead. **That role has since moved to
`https://delphigt.com/consent`** (a static page on the delphigt.com marketing site).

## Deploying changes

**Moot post-rebrand** — this repo is not the live consent page. GitHub Pages still
auto-builds from `main` root, but the live consent landing is generated by
`entra-claude-app/brand/web/_build_consent.py` and served at `https://delphigt.com/consent`.
Make consent-page changes there.

## Notes

- `<meta name="robots" content="noindex, nofollow">` on the page — we don't
  want search engines indexing a generic consent-landing URL.
- No JS, no external dependencies, no tracking. Pure static HTML + CSS.
- The page is intentionally generic: no client-specific identifiers, no
  session state. It was reached only from a successful consent flow.
